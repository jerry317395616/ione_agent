# 分析童健云已有食谱

只分析童健云中已经保存的真实食谱。先准确找到食谱，再调用服务端确定性分析工具；不要让模型自行估算食材、带量或营养成分。

## 工作流

### 1. 确认分析对象

1. 用户给出食谱内部编号时，调用 `frappe_get_document` 读取 `Tongjianyun Recipe`。
2. 用户只给出名称、周次或日期时，调用 `frappe_list_documents`：
   - `doctype` 固定为 `Tongjianyun Recipe`；
   - `fields` 使用 `name`、`recipe_id`、`title`、`week_start`、`week_end`、`workflow_status`、`is_deleted`、`modified`；
   - 按明确日期或状态设置 `filters`；无法直接过滤名称时，取最近记录并用返回字段匹配；
   - 排除 `is_deleted = 1` 的记录。
3. 只允许在唯一匹配后继续：
   - 没有匹配时说明没有找到，并回显用户给出的条件；
   - 多条匹配时列出“编号、名称、日期范围、状态”，请用户选择；
   - 不根据相似名称或上一次对话擅自选择。
4. 对唯一匹配调用 `frappe_get_document` 回读，使用返回的 `name` 作为后续 `recipe_name`。食谱标题不能代替内部编号。

### 2. 生成分析报告

1. 调用 `frappe_generate_tongjianyun_recipe_analysis`，只传唯一确认的 `recipe_name`。
2. 除非用户明确提供了经过确认的营养标准覆盖值，否则省略 `standard`，使用童健云配置的学龄前儿童标准。
3. 该工具会读取实际菜品和食材明细、按实际就餐人数或覆盖天数计算、生成与业务模板一致的 Excel，并作为私有文件附加到食谱。
4. 重复分析同一食谱时仍调用同一工具。服务端替换同名旧报告，避免产生多个难以辨认的版本。

## 数据边界

- 不创建或修改 `Tongjianyun Recipe`、菜品、食材和就餐人数记录。
- 不补写食谱中不存在的食物名称；所有食物必须来自目标食谱。
- 不用语言模型计算能量、蛋白质、脂肪、碳水化合物、矿物质或维生素。
- 不把附件中旧的 JSON、上一次上传的食谱或另一周食谱当作当前分析对象。
- 如果工具报告菜品、带量或食材缺失，明确指出数据不完整；不要伪造完整结论。
- 只有当前登录用户对食谱具有读取权限时才能分析；不要改用管理员身份绕过权限。

## 回答格式

工具成功后，简洁返回：

1. 食谱名称和内部编号；
2. 日期范围；
3. 实际分析的食材数；
4. 使用的营养标准画像；
5. 服务端返回的分析结论；
6. 使用 `download_url` 生成“下载食谱带量分析报告”的 Markdown 链接。

不得只说“已经生成”而遗漏下载链接。工具失败时保留原始食谱不变，并说明是未找到、权限不足、数据不完整还是报告生成失败。

详细工具参数和结果字段见 [分析契约](references/analysis-contract.md)。
